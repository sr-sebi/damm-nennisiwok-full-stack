# PLAN · Prueba Dorsal

Plan de trabajo y bitácora del desarrollo. Cada tarea tiene criterios de aceptación medidos sobre `samples/`;
la bitácora recoge qué se comprobó en cada una y qué hubo que corregir. El análisis previo está en `ANALISIS.md`.

## Flujo de trabajo

- **Orquestador** = sesión principal de Claude Code. Lleva este plan, revisa el diff de cada tarea, pasa las comprobaciones (pytest, `ruff check`, `ruff format --check`, `makemigrations --check`, `npm test`, `npm run lint`, `npm run build`, todo en Docker), hace el commit y apunta en la bitácora qué se comprobó y qué se corrigió.
- **Reparto**: T1–T6 y T9 las hizo el orquestador; T7 (frontend) y T8 (correo) fueron a subagentes, cada uno en su worktree, en paralelo con T9 y con el contrato de la API fijado en T6.
- **Revisor**: un subagente independiente revisó la rama completa antes de T10.
- Cada corrección del orquestador o hallazgo del revisor se apunta en la bitácora: es la materia de «Dónde se equivocó la IA» en `ENTREGA.md`.
